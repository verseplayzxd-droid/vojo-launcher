- Preserve every existing notice/header; package verbatim license texts and clearly expose unresolved inherited licenses. No relicensing.

The old KSP 2.2.10-2.0.2 failed because it registered generated sources using `kotlin.sourceSets` under built-in Kotlin. The prohibited `android.disallowKotlinSourceSets=false` override was not added. KSP 2.3.6 is the minimum recommended by the [Android AGP 9 migration guidance](https://developer.android.com/agents/skills/build-system/agp/agp-9-upgrade/skill). KSP 2.3+ numbering is independent of the Kotlin compiler; see the [Kotlin-maintained compatibility matrix](https://github.com/Kotlin/kotlin-agent-skills/blob/main/skills/kotlin-tooling-agp9-migration/references/VERSION-MATRIX.md).

Direct downloaded AAR manifest checks: Hilt 2.59.2 declares minSdk 14; Compose UI 1.8.3, Material 3 1.3.2, Activity Compose 1.9.3, and both Lifecycle Compose 2.8.7 artifacts declare 21; DataStore Preferences Android 1.1.7 declares 19. These checks do not replace the final merged manifest and assembleDebug verification.

Resolution detail: Hilt 2.59.2 requests Kotlin **stdlib 2.2.20** transitively. This does not change the built-in Kotlin compiler or Compose compiler plugin, which remain **2.2.10**. The actual UI Kotlin compilation and generated Hilt Java compilation passed with these versions. No metadata compatibility override was added.

The dependency/application-ID foundation build passed in 10m 32s (93 actionable tasks). Its merged debug manifest declares minSdk 21 and `io.github.verseplayzxd_droid.vojo.debug`. The final UI build and APK verification are recorded below.

## Verification commands

Use the existing V: workspace alias. If absent after a reboot, run `subst V: "F:\vojo launcher"`; first check that V: is unused, and do not overwrite another mapping. The ignored `.gradle` tooling/SDK directories were prepared in M1. JDK 8 is made discoverable through `.gradle/user-home/gradle.properties` (`org.gradle.java.installations.paths=V:/.gradle/tooling/jdk8/jdk8u504-b01`). A fresh machine needs the declared SDK packages from CI, a JDK 21 build JVM and JDK 8 compiler; paths below describe this prepared host.

```powershell
Set-Location V:\
$env:JAVA_HOME = 'C:\Users\Yashpc\.jdks\ms-21.0.9'
$env:ANDROID_HOME = 'V:\.gradle\android-sdk'
$env:ANDROID_SDK_ROOT = $env:ANDROID_HOME
$env:GRADLE_USER_HOME = 'V:\.gradle\user-home'
$env:JAVA_OPTS = '-Xmx256m -Xms32m -XX:+UseSerialGC'
$env:JAVA_TOOL_OPTIONS = '-Djava.net.preferIPv4Stack=true -Dsun.net.client.defaultConnectTimeout=15000 -Dsun.net.client.defaultReadTimeout=60000'
.\gradlew.bat :app_pojavlauncher:assembleDebug --no-daemon --max-workers=1 '-Dorg.gradle.jvmargs=-Xmx1024m -XX:+UseSerialGC' '-Pkotlin.compiler.execution.strategy=in-process' --console=plain --stacktrace
```

The smaller heap is a local build-host accommodation after JVM allocation failures; no runtime memory defaults or dependency versions were changed to hide those failures.

Expected: `BUILD SUCCESSFUL`, and `app_pojavlauncher/build/outputs/apk/debug/app_pojavlauncher-debug.apk`. Verify:

```powershell
$apk = 'F:\vojo launcher\app_pojavlauncher\build\outputs\apk\debug\app_pojavlauncher-debug.apk'
& 'C:\Users\Yashpc\AppData\Local\Android\Sdk\build-tools\36.0.0\apksigner.bat' verify --verbose $apk
& 'C:\Users\Yashpc\AppData\Local\Android\Sdk\build-tools\36.0.0\aapt.exe' dump badging $apk
& 'C:\Users\Yashpc\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe' scripts/verify_debug_apk.py $apk
```

Expected: verified v1/v2 debug signatures, package `io.github.verseplayzxd_droid.vojo.debug`, minSdk 21, target SDK 34, launcher `net.kdt.pojavlaunch.ui.vojo.VojoActivity`, 8 verbatim legal documents and 5 valid AArch64 ELF headers. ELF validity is not proof of runtime compatibility.

## Known limits and next milestone

The new shell is a development preview. Inherited authentication/token files and native launch paths have not yet received the M3 security/ownership work, and are not wired to the new shell. No fabricated success, account, profile, recent world, download or entitlement is used. No Android Java runtime is bundled; game acceptance remains M5. Extra obsolete JNA ABI entries inherited in the APK do not establish supported gameplay architectures.

The unresolved inherited licenses and privacy contact/policy need owner review before public release. Existing Gradle deprecation, localization-format, native and duplicate-library-namespace warnings remain; they are recorded, not silenced. Target SDK remains the inherited 34 and must be revisited for distribution in M10.

Next: **M3 Authentication** — Microsoft login, ownership check, Keystore-backed token storage, account switching and explicit errors. Stop for owner review after M2; no M3 implementation is included here.

M2 does not complete the ownership/token-storage changes scheduled for M3 or the entitlement backend scheduled for M9. New UI must not fabricate successful authentication or an active unlock.
